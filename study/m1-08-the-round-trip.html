The Round-Trip

🎯  Goal: your backend's JSON, rendered on the Vue page 🏁  This completes Milestone 1 — your MVP foundation 🧩  Concept: reactivity + lifecycle + rendering
Read me first

You proved the data path in the console: fetch → /api/test-php-array → your JSON, no CORS error. The only thing left is to make Vue do it — fetch when the page loads, hold the result, and draw it on screen. That's the finale of Milestone 1: a real, end-to-end round-trip.

This is your first real Vue code, so I'll teach the three moving parts with small generic examples — then you assemble them in App.vue using the fetch you already know. I'm deliberately not handing you the finished component; wiring it yourself is the whole point.

01Showing remote data needs three things

Any component that displays data from a server needs to answer three questions. The rest of this lesson is one Vue tool per question:

QuestionVue tool
Where do I keep the data so the UI updates when it arrives?a reactive ref()
When do I fetch it?the onMounted() lifecycle hook
How do I show it?template rendering — {{ }} and v-if

02Reactivity: a value the UI watches (ref)

Here's the core idea that makes Vue "Vue." If you keep data in a plain variable and change it, the page does not update — Vue has no idea anything happened. Wrap it in a ref() and Vue tracks it: whenever the value changes, every part of the template that uses it re-renders automatically. That auto-update is "reactivity."

vue — a reactive counter (illustrative, NOT your task) 
<script setup>
import { ref } from 'vue'

const count = ref(0)          // a reactive value, starting at 0
</script>

<template>
  <button @click="count++">clicked {{ count }} times</button>
</template>

Click the button and the displayed number updates itself — you never touch the DOM. You changed count; the template re-rendered because it's reactive.

The .value gotcha — everyone trips on this once

A ref stores its contents under .value. So the rule is:
• In JavaScript (inside <script>), read and write count.value — e.g. count.value = 5.
• In the template, write just count — Vue auto-unwraps it, so {{ count }} (not {{ count.value }}).
Forgetting .value in JS is the #1 "why isn't my data updating?" bug. Keep it in mind when you assign your fetched data.

Bridge — React, lightly

If useState flickers a memory: ref is the same "state that re-renders the UI when it changes" idea — except you mutate it directly via .value instead of calling a setter. If that comparison doesn't help, drop it; "a variable the UI watches" is all you need.

03When to fetch: onMounted()

A component has a lifecycle: it's created, then mounted (added to the real page), and eventually unmounted. onMounted() registers a function to run right after the component lands on the page — the conventional spot to kick off a side effect like a network request.

vue — onMounted (illustrative, NOT your task) 
<script setup>
import { onMounted } from 'vue'

onMounted(() => {
  console.log('the component is now on the page')
})
</script>

Could you fetch at the top of <script setup> instead? Often it would even work — a non-awaited async call there doesn't block the first render either, and the data still fills in reactively wherever you kick the fetch off. But onMounted is the right home for a side effect like this: it runs right after the component is actually on the page (so it's safe if your code ever touches the rendered DOM), it's skipped during server-side rendering, and it's the conventional lifecycle hook for side effects — which makes your intent obvious to the next reader. (React bridge: it's the job useEffect(() => {…}, []) does.)

04Showing it: {{ }} and v-if

Two bits of template syntax carry you here. {{ expression }} ("mustache" interpolation) drops a JS value into the HTML. v-if renders an element only when a condition is truthy (with an optional v-else).

vue — interpolation + a loading guard (illustrative) 
<template>
  <p v-if="user">Hello, {{ user.name }}</p>
  <p v-else>loading…</p>
</template>
Why the v-if guard matters

Your data ref starts empty (say null) and only fills in once the fetch resolves — a few milliseconds later. If the template tries to read data.name while data is still null, you get a render error. v-if="data" means "only render this once data exists," with v-else showing a placeholder until then. It's how you handle the gap between "page loaded" and "data arrived."

05Assembling it in App.vue

Now combine the three pieces with the fetch from M1-06. I'm giving you the recipe, not the code — each step maps to something you've already seen:

1
Declare a place to hold the data
In <script setup>, import ref and onMounted. Make a ref that starts empty (null) — it'll hold your fetched object.
2
Write an async function that fetches and stores
The same two-await fetch you ran in the console (to /api/test-php-array), reading res.json() once — then assign the result into your ref (remember .value!).
3
Call it on mount
Invoke that function inside onMounted(...) so it runs when the component appears.
4
Render it
Replace the scaffold's <template> with your own: a v-if loading guard, then {{ }} to show the fields (name, age, email).
Gut the scaffold

Delete the demo bits in App.vue — the HelloWorld / TheWelcome imports and their tags in the template. This is your component now. (Your committed scaffold means you can experiment fearlessly and git restore if you want the original back.)

06The full round-trip — every M1 lesson, one path

When it works, trace what just happened. Every concept of Milestone 1 is one hop in this chain:

the journey of one piece of data 
Route handler returns a PHP array        (M1-02)
        ↓  Laravel auto-serializes
JSON over HTTP, from /api, CORS-allowed  (M1-07)
        ↓  fetch + await res.json()
a JavaScript object                      (M1-06)
        ↓  stored into a ref (.value)
reactive state Vue is watching           (this lesson)
        ↓  {{ }} in the template
pixels on the screen                     🎉

That is a full-stack round-trip: your PHP backend and your Vue frontend, two separate apps, exchanging real data over HTTP. It's the "Plumbing" milestone's whole reason for being — and the spine every future feature hangs off.

You're done — and M1 is complete — when

Your backend's { name, age, email } renders on the Vue page, fetched on mount into a reactive ref, committed and pushed — and you can explain the .value-in-script-but-not-in-template rule and why the fetch lives in onMounted. That's a working full-stack round-trip: Milestone 1 done.

If the page is blank or stuck on "loading…"

Open the console and Network tab. Common causes: forgot .value when assigning (data never fills → stuck loading); wrote .value in the template (undefined); read data.name without the v-if guard (render error before data arrives); or the wrong URL (needs the /api prefix).
